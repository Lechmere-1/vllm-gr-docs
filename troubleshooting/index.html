    Troubleshooting¶

    Start with the first specific error in the engine or Worker log. A final Engine core initialization failed message usually summarizes an earlier failure. Keep the model, inputs, and command unchanged while isolating one cause. Use Quickstart for the supported first-run configuration.

    Files are missing or tee cannot create a log¶

    Symptom Check Action
    FileNotFoundError for a relative catalog or prompt path The shell's current directory Run the examples from the vllm-gr source repository root.
    Model directory is missing or incomplete Local weights, config.json, and tokenizer files Download the model separately; the repository does not contain its weights.
    tee: ... No such file or directory The log's parent directory Create that directory before running the pipeline.
    Variables work in one terminal but not another Variables in the active shell Set the paths again in the new terminal, as the online guide does.

    After setting the paths in First offline inference:

    pwd
test -f "$MODEL/config.json"
test -f "$CATALOG"
test -f "$PROMPT"
mkdir -p "$WORKDIR/logs"
set -o pipefail

    pipefail makes an inference failure visible when output is piped through tee. It does not create directories or repair an invalid path.

    Python imports the wrong checkout or runtime¶

    Check the interpreter and the actual package location in the shell that starts the engine:

    python --version
python -m pip --version
python -c 'import sys, vllm_gr; print(sys.executable); print(vllm_gr.__file__)'

    If the import path points to an unexpected environment or checkout, activate the intended environment and install this checkout using its platform guide. Use python -m pip to target that interpreter. Installing GR does not provision or upgrade the Ascend vendor stack. Installing into one Python environment does not repair another environment.

    Run vllm-gr check-env for CUDA or vllm-gr check-env --npu for Ascend. These checks establish runtime compatibility, not successful model inference, operator execution, or sufficient device memory.

    Ascend dependencies or custom operators fail to load¶

    The source version behind these guides requires vLLM 0.30.0, vLLM-Ascend 0.30.0rc2, and Triton-Ascend 3.6.0 from the prepared vendor environment. Follow Ascend installation; an environment named after an older release does not become compatible just by installing GR.

    Symptom Check Action
    Unsupported vLLM or vLLM-Ascend version The active interpreter's package versions Return to the matching vendor image instead of mixing release stacks.
    Triton-Ascend is installed but its backend is missing The active triton module, reported by check-env --npu Resolve the shared-package overwrite described by the error; standard Triton metadata alone is insufficient.
    custom_ops_lib cannot be imported or a shared library is missing CANN, the installed custom operator environment, and the active Python Load the CANN and custom xllm-ops environments from the installation guide in this shell.
    A required binding is missing The installed xllm-ops build and exported callables Build the required operator subset for this image's CANN version and reinstall its Python binding.

    The Python binding is named custom_ops_lib. custom_xllm_math is the CANN vendor directory, not the Python module name. On the prepared NPU host, this checks binding exposure without launching an inference request:

    python - <<'PY'
from vllm_gr.ops.npu._xllm_loader import custom_ops

ops = custom_ops()
if ops is None:
    raise SystemExit("custom_ops_lib is unavailable; check the installed runtime and loader logs")

names = (
    "cache_unshared_kv", "x_attention", "select_unshared_kv",
    "beam_search_group", "beam_search_rec_final_select", "rec_constrained_topk",
)
for name in names:
    print(name, callable(getattr(ops, name, None)))
PY

    Successful import and callable checks do not establish ABI compatibility or successful execution on the device. Keep the original loader error if this fails. Do not reuse custom operators compiled for a different CANN stack. Attention's cascade fallback does not supply a missing catalog-constrained TopK operator: that resolver has no Torch fallback. See the binding loader and constrained TopK resolver.

    Keep pip check reports as diagnostics. The vendor image has documented metadata discrepancies; distinguish those from a new missing dependency or a failed NumPy/cv2 import, as explained in the Ascend installation guide.

    Engine startup reports insufficient free memory¶

    Read the reported free memory and requested utilization. The startup check can fail before inference when other jobs occupy the device. Check the allocated device with nvidia-smi or npu-smi info, according to your platform.

    Use a free device through your environment's allocation process. Stop only your own unneeded inference jobs; do not terminate other users' processes. gpu_memory_utilization also applies on NPU. Lower it only when enough memory remains for weights, KV storage, and execution buffers; lowering it blindly can move the failure to a later allocation. Wider Beams and additional graph captures can require more memory. A memory-admission error alone is not a numerical-accuracy failure.

    An argument is unknown or configuration sources conflict¶

    Configuration layer Put settings here
    GR engine configuration beam and constraint_table in --vllm-gr-config YAML or the Python vllm_gr_config mapping.
    Native engine configuration Supported GRLLM/serve options such as max_model_len, async_scheduling, and gpu_memory_utilization.
    Beam request Python BeamSearchParams, or HTTP fields and supported vllm_xargs entries.
    Platform extension Only keys and nesting supported by the installed vLLM-Ascend release's additional_config.

    An EngineArgs.__init__() got an unexpected keyword argument error means the argument was not accepted at that layer. Do not pass platform switches such as enable_npugraph_ex as arbitrary top-level GRLLM keywords. Check the exact vendor release's configuration contract before moving a setting elsewhere.

    Do not combine canonical GR configuration with legacy GR catalog, attention, or Beam overrides in CLI options or additional_config. Restore the complete online example before adding custom settings. Keep async_scheduling=True, Chunked Prefill disabled, and request width equal to beam.max_width. HTTP n is this Beam width, not a display limit. See Beam parameters and modes and the configuration boundary.

    A graph does not replay, or fallback counts increase¶

    On NPU, first confirm the eager example works. Then select graph execution without changing the inputs. For serving, enable beam.graph_enabled, remove --enforce-eager, and restart the engine. The offline demo's --execution option controls NPU; it does not switch CUDA into eager mode.

    Inspect npu_beam_graph counters from the NPU graph example:

    Observation Interpretation or action
    No Decode replay for one generated component Expected: this request finishes in Prefill.
    Missing (B, input_width) in captured_shapes Configure the exact logical batch size and Decode input widths before engine startup.
    Increasing fallbacks Inspect fallback_reasons; Beam FULL was not used, but execution need not be purely eager.
    More dispatches than measured Decode steps Counters include warmup as well as measured or profiled requests.

    For retained widths [128, 64, 32], Decode inputs are 128 and 64, not 32. Capture only the needed shapes. Prefill capture has separate controls and precision limits. Configuration flags alone are not replay evidence; inspect the counters and a separate profile. See graph shape configuration.

    SID candidates, scores, or ranking differ¶

    Compare the same model/tokenizer snapshot, catalog, prompt token IDs, dtype, batch size, generation budget, candidate domain, widths, and cache policy. The direct offline demo truncates or pads to --input-len; the HTTP example does not apply that preprocessing. Identical prompt text alone is insufficient.

    Compare ordered sequences, candidate sets, and scores for matching sequences separately. A different Beam schedule or full-vocabulary versus SID-family normalization changes the search semantics. Catalog-free SID stages do not guarantee that a generated combination identifies a known item. Valid SIDs also do not establish unchanged recommendation quality.

    For NPU, the recorded exact-bucket tests do not resolve the open padded-Prefill precision limitation. Do not claim arbitrary mixed-length Graph/Eager parity from a passing bounded case. Isolate Decode with Prefill graphs disabled when following the recorded reproducer, and preserve its input conditions. See Validation and benchmarking and the documented precision scope.

    HTTP requests or artifact validation fail¶

    Symptom Check Action
    Connection refused Server startup, host, and port Keep the server running and use the address selected in the online guide.
    Model not found /v1/models and --served-model-name Send the configured alias, onerec in the guide.
    Artifact or tokenizer digest mismatch Artifact path, both digests, and tokenizer snapshot Rebuild the artifact and YAML together; do not edit a digest to bypass validation.
    Triples JSON supplied as a server catalog Artifact format Compile a persistent .safetensors table for the online service.
    Width or budget error Request n, server capacity, and boundary positions Keep width 128; max_tokens=5 with begin/end reserves three generated components.

    Read the response error body and the first specific server error. A length finish reason can be normal for fixed-budget Beam; it is not automatically a failed generation. Follow Online serving for the complete request and artifact setup.

    Collect a small diagnostic record¶

    Run these basic checks in the failing environment; they do not run inference:

    python --version
git rev-parse HEAD
python -m pip --version
python - <<'PY'
from importlib import metadata, util

for name in ("vllm-gr", "vllm", "vllm-ascend", "torch", "torch-npu", "triton-ascend"):
    try:
        print(name, metadata.version(name))
    except metadata.PackageNotFoundError:
        print(name, "not installed")
for name in ("vllm_gr", "vllm", "torch", "triton"):
    spec = util.find_spec(name)
    print(name, "module:", None if spec is None else spec.origin)
PY

    Record the selected device and runtime-check result, the first error and nearby context, the exact command, relevant graph settings, and whether eager works. For a numerical issue, include model/input identity and matching token/score evidence. For performance, include the timing boundary and repeated samples. Remove credentials, private paths, and private endpoint names before sharing. Do not dump the full environment, credential files, or authentication headers.
