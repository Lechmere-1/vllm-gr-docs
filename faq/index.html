    Frequently asked questions¶

    Which model should I use first?¶

    Use OpenOneRec/OneRec-1.7B and its tokenizer, as in Quickstart. This first documentation edition presents it as the main CUDA/NPU recommendation model. Pangu is an additional NPU-only guide; it is not part of the GPU model walkthrough.

    Are model weights included in the repository?¶

    No. Download them separately. Keep configuration, weights, and tokenizer from the same snapshot. The bundled triples fixture is catalog data, not a model. See Data and constraints.

    Are catalog JSON, triples JSON, and the artifact interchangeable?¶

    No. Raw catalogs contain token-string sequences; the converter writes triples and relations. The artifact builder combines triples with a tokenizer and model vocabulary dimension. The online service loads the resulting .safetensors artifact, while the standalone offline demo compiles a temporary table itself.

    Does Beam width 128 mean generating 128 tokens?¶

    No. It is search/storage capacity. With the OneRec begin and end positions, max_tokens=5 searches three SID components. A return limit changes the final sequence count; --print-beams only changes display. See the parameter reference.

    Does a candidate limit preserve every parent?¶

    No. Parents contribute candidates that still compete globally. A parent may produce several winners or none. The selected parent indices must also govern KV inheritance. See Beam Search explained.

    Can dynamic Beam both narrow and widen?¶

    Yes, within the current capacity and platform rules. Widening branches from surviving prefixes; it cannot recover previously pruned prefixes. Changing the schedule changes the search and can change recommendation quality.

    Does a graph-enabled flag prove graph execution or equal scores?¶

    No. Check actual captures, dispatches, and fallback reasons. Numerical parity needs a separate comparison. In particular, the recorded NPU padded-Prefill limitation is not resolved by passing an exact-bucket test. See Validation and benchmarking.

    Is offline inference always synchronous?¶

    The public GRLLM.beam_search_v1() call is synchronous, while its engine uses asynchronous scheduling internally. Async engine integration can also run without HTTP, but this snapshot has no exported GRAsyncLLM convenience class. See Python integration.

    Does a valid SID prove recommendation accuracy?¶

    No. A catalog constrains legality. Recall needs the correct dataset, business mapping, and acceptance policy. Pangu's random SID conversion can exercise the execution path without supplying trained recommendation knowledge.

    Why can fewer than 128 candidates be returned?¶

    The valid catalog or configured result limit may be smaller than capacity. Invalid slots do not create recommendations. A failed request or a session with no valid final beams must be investigated as an error.

    Does CI mean hardware accuracy and performance passed?¶

    CI means continuous integration. A particular job may only check formatting, schema, packaging, or collection. Read the actual jobs, skips, hardware inputs, and evidence. See Testing and CI.

    Where are Maintainers and Committers listed?¶

    Those roles have not been finalized for this documentation edition. The governance page reserves their sections without assigning names or inferring roles from PR counts, repository access, or documentation ownership.
