    Public Pangu on Ascend NPU¶

    This guide covers openpangu/openPangu-Embedded-1B-V1.1 using the vLLM-GR source snapshot c4966f18. Pangu is an additional NPU workflow, separate from the main OneRec tutorial. It has two paths:

    Workflow Input checkpoint Purpose
    Ordinary text inference Untouched public weights and tokenizer Run the repository's Pangu text-generation example and inspect its small arithmetic fixture.
    Constrained SID Beam smoke test A separate checkpoint prepared from those public assets Exercise SID tokenization, vocabulary rows, and the existing constrained Beam pipeline.

    The SID workflow does not train recommendation behavior. Its new weight rows are random, and its catalog is synthetic. A legal SID is not evidence of business accuracy, useful rankings, or a performance improvement.

    The converter expects this public checkpoint's architecture, original vocabulary, tied embeddings, and safetensors layout. Do not apply these steps to arbitrary Pangu models or an already extended checkpoint. See Models and capabilities for the component roles.

    1. Prepare the platform and paths¶

    Complete Ascend installation. Run these Bash commands from the vllm-gr source repository root, in the prepared vendor runtime's Python environment. Keep the CANN and custom xllm-ops environments loaded. Use an allocated NPU with sufficient free memory, and stop your own other inference workloads.

    export PANGU_PUBLIC_REVISION=146d3a854e2930b5e3dfbf9dc1187a6c78f8decd
export PANGU_PUBLIC_MODEL_PATH="$PWD/models/openPangu-public-$PANGU_PUBLIC_REVISION"
export PANGU_SID_MODEL_PATH="$PWD/models/openPangu-public-sid-seed20261105"
export PANGU_WORKDIR="$PWD/results/pangu"
export VLLM_USE_V2_MODEL_RUNNER=0
mkdir -p "$PANGU_WORKDIR/logs" "$PANGU_WORKDIR/json"
set -o pipefail

    The public revision is the snapshot recorded by the conversion tool. Download it into the source directory; do not edit that directory or use it as the conversion output:

    python - <<'PY' 2>&1 | tee "$PANGU_WORKDIR/logs/download.log"
import os
from huggingface_hub import snapshot_download

path = snapshot_download(
    repo_id="openpangu/openPangu-Embedded-1B-V1.1",
    revision=os.environ["PANGU_PUBLIC_REVISION"],
    local_dir=os.environ["PANGU_PUBLIC_MODEL_PATH"],
)
print(f"model={path}")
print(f"revision={os.environ['PANGU_PUBLIC_REVISION']}")
PY

    Keep weights, configuration, tokenizer, and any model-provided code from the same snapshot. Model downloads require network access and enough disk space; see the Hugging Face download guide for authentication and cache options. Reuse a local copy only if it is the untouched matching snapshot.

    2. Run ordinary text inference¶

    The Pangu example uses GRLLM.generate() and ordinary sampling parameters. It does not enable SID Beam or need a Constraint Table. The source selects BF16, the slow tokenizer, and disables Chunked Prefill and Prefix Cache; its NPU path uses KV block size 128. This ordinary text path is not the width-32, three-step SID Beam path used later in this guide.

    These commands use the checked-in eight-question arithmetic fixture. A smaller context limit is sufficient for this example; it is not the model's advertised maximum context length:

    PANGU1B_MAX_MODEL_LEN=2048 \
python -u examples/offline_inference/pangu1b/pangu_generate.py \
  --model "$PANGU_PUBLIC_MODEL_PATH" \
  --dataset-path tests/resources/pangu1b/gsm8k_mini.json \
  --num-prompts 8 --max-tokens 256 --temperature 0.0 \
  --tensor-parallel-size 1 --gpu-memory-utilization 0.5 \
  --block-size 128 --min-accuracy 0.5 \
  --output-json "$PANGU_WORKDIR/json/text-npu.json" \
  2>&1 | tee "$PANGU_WORKDIR/logs/text-npu.log"

    The script prints accuracy, correct, num_samples, and elapsed_time, and saves generated answers and extraction details in the requested JSON. The explicit 0.5 is this example script's default threshold, not the CI policy. A nonzero exit when the threshold is missed is an evaluation failure, which is different from an engine startup error; inspect the saved details.

    The arithmetic score is neither recommendation Recall nor a broad reasoning benchmark. elapsed_time includes engine construction and generation; it is not a steady-state request-latency measurement. The compatibility layer preserves the public checkpoint's tied embedding behavior instead of treating its zero output-head placeholder as an independent learned head.

    For ordinary Pangu HTTP text serving, use the source example. Do not attach the OneRec constrained service configuration to ordinary text generation. The remainder of this page creates a different checkpoint for SID execution only.

    3. Prepare a separate untrained SID checkpoint¶

    At this source snapshot, the project's SID-extended Pangu checkpoint is not publicly available. The conversion tool provides a reproducible execution fixture using public weights, without introducing a new Pangu network implementation.

    Preparation runs on CPU and requires torch, safetensors, transformers, sentencepiece, and protobuf. huggingface_hub is needed for the download. An installed vLLM-GR accelerator environment already supplies its compatible Torch and Transformers stack; keep those wheels, especially the Ascend vendor packages. If helper packages are missing, install only the missing helpers:

    python -m pip install sentencepiece protobuf huggingface_hub

    CPU preparation can instead run in a separate isolated environment containing those dependencies; it needs no accelerator or installed vLLM-GR. Install any CPU Torch wheel only in that separate environment, then return to the matching accelerator environment for inference. Do not replace vendor Torch/torch-npu merely to run this preparation tool.

    The destination must not already exist and must be separate from the source. Do not create PANGU_SID_MODEL_PATH with mkdir. To prepare a different run, choose a new output directory rather than overwriting a checkpoint:

    python -u tools/model_conversion/prepare_pangu_sid.py \
  --source "$PANGU_PUBLIC_MODEL_PATH" \
  --source-revision "$PANGU_PUBLIC_REVISION" \
  --output "$PANGU_SID_MODEL_PATH" \
  --seed 20261105 \
  2>&1 | tee "$PANGU_WORKDIR/logs/conversion.log"

    The tool stages the output and publishes its directory after CPU validation. Its completion status is converted_and_cpu_validated; this is not an accelerator inference test. The prepared checkpoint contains:

    • Existing token IDs and original embedding rows, with other model tensors preserved.
    • 8192 symbols per A, B, and C family plus SID BEGIN/END markers; new embedding and padding rows are initialized randomly using the fixed seed.
    • A tied lm_head.weight materialized from the expanded embedding, replacing the public zero placeholder, plus updated vocabulary metadata.
    • sid_token_ids.json, conversion_tensor_inventory.json, and conversion_manifest.json for token layout, checksums, and validation results.

    This changes tokenizer assets and weight storage. Preserving the original embedding prefix does not make the full checkpoint unchanged or guarantee identical ordinary text output after vocabulary expansion. No training has taught the random rows a relationship to real items.

    --source-revision is a declaration. The manifest hashes the actual local files but reports revision_verified: false; it does not authenticate those files against the remote revision. Keep converted weights and local conversion reports outside source control.

    4. Build a synthetic catalog and triples¶

    The catalog below contains every combination of eight A, eight B, and eight C symbols: 512 complete triples. It is a functional fixture with enough final paths for Beam width 32, not a business item mapping or evaluation dataset.

    python - <<'PY'
import itertools
import json
import os
from pathlib import Path

work = Path(os.environ["PANGU_WORKDIR"]) / "sid-inputs"
work.mkdir(parents=True, exist_ok=True)
catalog = [
    ["<|sid_begin|>", f"<s_a_{a}>", f"<s_b_{b}>", f"<s_c_{c}>", "<|sid_end|>"]
    for a, b, c in itertools.product(range(8), repeat=3)
]
(work / "catalog.json").write_text(json.dumps(catalog, indent=2) + "\n", encoding="utf-8")
(work / "prompt.txt").write_text("Return a semantic ID for this request.\n", encoding="utf-8")
print(f"catalog_entries={len(catalog)}")
PY

python tools/build_constraint_triples.py \
  --catalog "$PANGU_WORKDIR/sid-inputs/catalog.json" \
  --output "$PANGU_WORKDIR/sid-inputs/constraint_triples.json" \
  --begin '<|sid_begin|>' --end '<|sid_end|>' \
  2>&1 | tee "$PANGU_WORKDIR/logs/build-triples.log"

    Pass the resulting triples document to the Beam demo, not the raw list in catalog.json. Every symbol must be present in the prepared tokenizer; do not substitute an unrelated public model directory. See Data and constraints for artifact identities and the separate persistent-artifact route used by applications and services.

    5. Run constrained SID Beam¶

    Return to the installed Ascend environment if preparation used a separate CPU environment. Retain the exported paths and custom operator environment in this shell:

    python -u examples/offline_inference/beam_search/offline_beam_search_v1.py \
  --model "$PANGU_SID_MODEL_PATH" \
  --catalog "$PANGU_WORKDIR/sid-inputs/constraint_triples.json" \
  --prompt "$PANGU_WORKDIR/sid-inputs/prompt.txt" \
  --constraint-backend npu --execution eager \
  --batch-size 1 --beam-width 32 --generated-steps 3 \
  --input-len 128 --max-model-len 2048 \
  --gpu-memory-utilization 0.5 --print-beams 5 \
  2>&1 | tee "$PANGU_WORKDIR/logs/sid-npu.log"

    The demo compiles a temporary Constraint Table, sets the engine and request widths consistently, and prints returned candidates. Its three generated SID components use public max_tokens=5 with BEGIN/END positions. The first component comes from Prefill; two Decode steps produce the remaining two.

    --input-len 128 prepares 127 prompt tokens plus the appended BEGIN position, using truncation or newline padding. This is a fixed-shape execution fixture, not evidence of unchanged prompt semantics or realistic recommendation quality. The SID command requests NPU eager execution. It does not establish graph replay or a performance comparison with the ordinary text workflow.

    The constrained table determines legal A/B/C combinations. Random SID weights determine their scores and ordering within that legal set, so valid-looking SIDs are expected and are not proof that the checkpoint learned recommendation. Inspect candidate IDs, boundary tokens, and the generated catalog together.

    This page documents the checked-in workflow; it does not report a new hardware qualification of these commands. Use Validation and benchmarking for device execution, numerical agreement, graph replay, and quality evidence. For an application integration after preparing a suitable persistent artifact, see Python integration. Do not copy its OneRec capacity 128 configuration unchanged into this width-32 fixture.
