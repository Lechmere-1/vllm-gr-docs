    Configuration reference¶

    Use the canonical schema-v1 configuration for GR engine settings. Native vLLM options, Beam request parameters, and process environment variables have different owners. Start with Data and constraints to generate a configuration containing real artifact paths and digests.

    Configuration layers¶

    Layer Python Serving
    GR engine lifetime vllm_gr_config mapping, YAML path, or GRConfig --vllm-gr-config YAML
    Native engine lifetime Supported GRLLM constructor options Native serve flags
    One Beam call BeamSearchParams and call arguments Completion fields and supported vllm_xargs
    Process/runtime Environment set before Python starts Environment inherited by server and Workers

    Do not mix canonical configuration with legacy catalog, attention, or Beam overrides. Unknown canonical keys are errors. The parser does not expand shell variables in YAML strings: generate actual paths rather than writing $MODEL or $WORKDIR into a file and expecting shell interpolation later.

    Top-level keys¶

    Key Schema default or requirement Usage
    schema_version Required; 1 Select the canonical configuration schema.
    attention_backend Unset These Beam guides explicitly use CUSTOM.
    constrained_generation Unset Leave unset for the enabled catalog table; explicitly false selects the separate unconstrained path.
    beam Empty mapping Select the Beam interface and storage/graph policies below.
    constraint_table Mapping with required max_top_k An enabled table additionally needs its artifact identity.

    Schema acceptance validates configuration structure; it does not prove device support, available memory, a readable artifact, matching weights, or inference.

    Beam engine keys¶

    Key under beam Schema default Meaning
    execution_mode Unset Set v1 for beam_search_v1().
    max_width Unset Persistent Beam capacity; match each request's width. Schema ceiling: 1024, with additional candidate/platform restrictions.
    max_decode_steps 3 Effective generation capacity, including the component selected by Prefill. This does not extend a three-level table.
    worker_decision Unset These V1 guides explicitly set true; platform admission still applies.
    graph_enabled true Enable the Beam Decode graph path when a Beam pool is configured.
    graph_batch_size 1 Exact NPU logical batch capture dimension, not scheduler capacity.
    graph_widths Unset Additional exact NPU Decode input widths; unique positive widths no greater than capacity.
    online_batch_sizes [1, 2, 4] Online batching policy; the first-run guides deliberately use [1]. Allowed logical sizes are 1 through 8.
    enable_short_suffix_attention true CUDA short-suffix attention optimization; not an NPU mode selector.
    prefill_flash_attn_version auto CUDA Prefill policy; accepted values are auto, null, 2, and 3.
    sid_stage_vocab false Opt into the NPU catalog-free A/B/C domain, with its separate requirements.
    engine_driven Retired Omit it. true is consumed with a warning; false is rejected.

    The NPU graph policy allows at most eight captured widths including the implicit maximum-width bank when Beam graphs are active. Numeric schema ceilings are not a supported-shape matrix. Use Beam parameters and modes and Serving and batching before changing widths or batches.

    Constraint Table keys¶

    Key under constraint_table Schema default or requirement Meaning
    max_top_k Required positive integer Candidate storage ceiling; execution and candidate limits still apply.
    enabled false Enable loading the canonical artifact.
    backend cuda Placement: cuda, npu, or cpu; CPU compilation/reference support is not production CPU Beam inference.
    path Unset Required for an enabled table; path to the saved .safetensors artifact.
    format constraint_table_v1 Three-level single-Trie format; constraint_table_v2 selects the separate multi-Trie format.
    artifact_digest Unset Required for an enabled table; use the builder's exact sha256: identity.
    tokenizer_digest Unset Required for an enabled table; use the builder's tokenizer identity.
    candidate_width Unset Independent scalar candidate count; platform and retained-width rules apply.

    When candidate width is unset it follows the retained-width policy. Capacity above 256 requires an explicit candidate width within the candidate ceiling. The independent candidate count is capped at 256 even though the schema does not impose that same numeric ceiling on max_top_k. NPU has stricter width-equality requirements; do not copy a CUDA-only setting into an NPU configuration because its schema accepts the integer.

    Paths in YAML resolve relative to that YAML file. A direct mapping requires an absolute artifact path unless the caller explicitly supplies a base directory to the parser. Digests validate compiled inputs; they are not model-weight checksums. Keep model, tokenizer, catalog, and mapping provenance separately.

    Inspect a prepared configuration¶

    With GR_CONFIG exported by the data-preparation guide:

    python - <<'PY'
import os
import yaml
from vllm_gr.config import gr_config_to_mapping, load_gr_config

config = load_gr_config(os.environ["GR_CONFIG"])
print(yaml.safe_dump(gr_config_to_mapping(config), sort_keys=False))
PY

    This parses and normalizes configuration without loading model weights. It does not load the artifact or verify its contents against the model. Engine startup performs additional checks.

    Native engine and request options¶

    These do not belong inside canonical beam or constraint_table:

    Native option Purpose
    max_model_len Model context limit.
    max_num_batched_tokens Scheduling token budget, including complete remaining Prefill and physical NPU Decode row requirements.
    max_num_seqs Native logical-request capacity; separate from physical Decode token rows and the exact online batch policy.
    max_logprobs Budget that must cover the required candidate count.
    gpu_memory_utilization Device-memory allocation target, including on NPU.
    async_scheduling Keep enabled for this V1 path.
    enable_chunked_prefill Keep disabled for this V1 path.
    enforce_eager Native execution control; pair it with GR graph policy for the intended run.

    Request width, generation budget, dynamic schedule, return limit, and boundary tokens are described in the Beam parameter reference. For additional_config platform extensions, use the installed vendor release's contract. The canonical GR schema does not accept arbitrary native or vendor keys, including enable_npugraph_ex.
