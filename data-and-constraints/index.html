    Data and constraints¶

    Model weights, tokenizers, catalogs, and business item mappings have different roles. This guide prepares one persistent Constraint Table and its canonical configuration for a local OneRec model on CUDA GPU or Ascend NPU.

    Complete installation and model preparation first. Run commands in Bash from the vllm-gr source repository root, using the matching Python environment. On NPU, keep the CANN and custom operator environments loaded. Preparation compiles data; it does not run model inference.

    Keep the files distinct¶

    Catalog JSON
    |
Triples + model config/tokenizer
    |
Constraint Table + digests
    |
YAML -> Python or HTTP

Generated SID
    |
Business mapping -> item(s)
    Input or output Contents Used by
    Model directory Weights, model configuration, and tokenizer assets Model loading; compilation reads the config and tokenizer
    Raw catalog JSON A list of legal token-string sequences tools/build_constraint_triples.py
    Triples JSON A/B/C token strings, sentinel metadata, and relations tools/build_constraint_table.py; the offline Beam demo
    .safetensors artifact Compiled token-ID relations and metadata The configured Constraint Table loader
    Canonical YAML Artifact identity and GR execution settings Python vllm_gr_config or --vllm-gr-config
    SID-to-item mapping Business identifiers and any mapping-selection metadata Your application or task evaluator

    The repository does not include model weights. Download them separately and keep the weights, configuration, and tokenizer from the same snapshot. Compiling a catalog does not train embeddings, update model weights, or teach the model which items a user prefers.

    1. Set the model, output directory, and backend¶

    Use the existing local OneRec snapshot from the first-inference guide. Adjust MODEL if it is stored elsewhere:

    export MODEL="$PWD/models/OneRec-1.7B"
export WORKDIR="$PWD/results/data-preparation"
mkdir -p "$WORKDIR"
test -d "$MODEL"
test -f "$MODEL/config.json"

    Choose the backend that will run inference:

    export BACKEND=cuda

    export BACKEND=npu

    The backend selects the runtime loader in the generated configuration. It does not turn the table into model weights or establish device execution coverage.

    2. Choose one triples input route¶

    Run either route A or route B, then continue with the common compilation step. Do not pass an arbitrary raw catalog to the artifact builder.

    Route A: reuse the repository's example triples¶

    For the shortest preparation path:

    export CATALOG="$PWD/tools/AB_Tests/constraints/video_constraint_triples.json"
test -f "$CATALOG"

    This file is already a triples document. Do not run the raw-catalog converter on it. Its name and the offline demo's --catalog argument do not mean every JSON file is accepted. The fixture is useful for execution checks; it is not a substitute for your business catalog, item mapping, or evaluation dataset.

    Route B: convert a raw catalog¶

    A raw catalog is a JSON list of sequences, not a mapping of token IDs to item IDs. This small format example contains two distinct legal triples:

    cat > "$WORKDIR/catalog.json" <<'JSON'
[
  ["<|sid_begin|>", "<s_a_1>", "<s_b_2>", "<s_c_3>", "<|sid_end|>"],
  ["<|sid_begin|>", "<s_a_1>", "<s_b_2>", "<s_c_4>", "<|sid_end|>"]
]
JSON

export CATALOG="$WORKDIR/constraint_triples.json"
python tools/build_constraint_triples.py \
  --catalog "$WORKDIR/catalog.json" \
  --output "$CATALOG" \
  --begin '<|sid_begin|>' \
  --end '<|sid_end|>'

    For real use, replace the input file with your model-aligned catalog before conversion. The two-row example can return at most two distinct complete SID paths; Beam width 128 does not create more legal items.

    The converter validates sequence shape, sentinel consistency, and exactly three semantic components, and rejects duplicate A/B/C triples. If every input sequence contains only the three components, omit --begin and --end. Use consistent wrapping within a catalog. Let the tool generate the document's format_version, triples, sentinels, and relations fields.

    Triples store token strings, not tokenizer IDs. The artifact compiler maps them using the selected tokenizer and model vocabulary size. Each catalog symbol must be a registered vocabulary entry with a valid, unambiguous token ID; an unknown token silently mapped to UNK is not a valid SID registration. Adding strings to the catalog does not add tokenizer entries or weight rows.

    3. Compile once and write the canonical configuration¶

    Both routes now provide CATALOG, a triples document. Run this common step once. It calls the real artifact builder used by the CLI and writes the resulting path and digests into YAML, avoiding manual copying:

    python - <<'PY'
import os
from pathlib import Path
import yaml
from tools.build_constraint_table import build_constraint_table
from vllm_gr.config import gr_config_from_mapping

backend = os.environ["BACKEND"]
if backend not in {"cuda", "npu"}:
    raise ValueError("BACKEND must be cuda or npu")
model = Path(os.environ["MODEL"]).resolve(strict=True)
if not model.is_dir():
    raise ValueError("MODEL must be a local model directory")
work = Path(os.environ["WORKDIR"]).resolve()
work.mkdir(parents=True, exist_ok=True)
artifact = work / "video_constraint_table.safetensors"
artifact_digest, tokenizer_digest, vocab_size = build_constraint_table(
    triples_path=os.environ["CATALOG"],
    model=str(model),
    revision=None,
    output_path=artifact,
    trust_remote_code=True,
)
config = {
    "schema_version": 1,
    "attention_backend": "CUSTOM",
    "beam": {
        "execution_mode": "v1",
        "graph_enabled": backend == "cuda",
        "graph_batch_size": 1,
        "online_batch_sizes": [1],
        "worker_decision": True,
        "max_width": 128,
        "max_decode_steps": 3,
    },
    "constraint_table": {
        "enabled": True,
        "backend": backend,
        "max_top_k": 128,
        "path": str(artifact),
        "format": "constraint_table_v1",
        "artifact_digest": artifact_digest,
        "tokenizer_digest": tokenizer_digest,
    },
}
gr_config_from_mapping(config)
config_path = work / "vllm_gr_config.yaml"
config_path.write_text(yaml.safe_dump(config, sort_keys=False), encoding="utf-8")
print(f"config={config_path}")
print(f"artifact_digest={artifact_digest}")
print(f"tokenizer_digest={tokenizer_digest}")
print(f"vocab_size={vocab_size}")
PY

export GR_CONFIG="$WORKDIR/vllm_gr_config.yaml"
test -f "$GR_CONFIG"

    This is the Python entry point of tools/build_constraint_table.py, not a second builder you must run afterward. Keep the artifact and YAML together. The YAML sets capacity 128, three effective generated components, a single HTTP batch size, and no independent candidate-width override. CUDA retains its graph path; NPU Beam graphs are disabled for the initial configuration. For a fully eager NPU run, also use the engine's enforce_eager=True or serving --enforce-eager, as shown in Online serving.

    The example uses a local model directory, so revision=None is intentional. The builder requires a revision for a remote model ID and resolves a symbolic revision before loading the tokenizer and configuration. For reproducible builds, preserve the local snapshot and record its immutable model revision.

    Understand the two digests¶

    Value Identifies Does not establish
    artifact_digest SHA-256 of the complete saved artifact bytes Recommendation quality or model-weight identity
    tokenizer_digest The canonical vocabulary, added vocabulary, and special-token role/ID state used by the compiler A checksum of the model's learned weights
    vocab_size Model-config vocabulary dimension used to validate IDs and load the table That arbitrary replacement weights are equivalent

    Use the returned digests exactly, including their sha256: prefix. The loader checks the artifact format, expected digest, tokenizer digest, and vocabulary size. Do not edit a digest to silence a mismatch. Rebuild the artifact and YAML when the catalog or tokenizer changes, and keep a separate record of the model weights and source revision. A moved file with unchanged bytes is different from a changed tokenizer or catalog behind the same path.

    The offline demo still compiles its own temporary table from --catalog; it does not automatically consume GR_CONFIG. Use the persistent table with the Python integration or the service's --vllm-gr-config. The latter still needs native engine settings such as asynchronous scheduling and disabled Chunked Prefill; this YAML alone is not a complete launch command.

    Map a complete SID back to business items¶

    The generated <s_a_1><s_b_2><s_c_3> symbols describe a complete SID. The numbers 1, 2, and 3 are SID components, not their tokenizer vocabulary IDs. The Constraint Table checks allowed combinations; it does not return business item details or contain the SID-to-item mapping's values.

    The OpenOneRec conversion convention encodes component values as:

    encoded_sid = A * 8192 * 8192 + B * 8192 + C

    The dataset's sid2pid.json maps these encoded SID keys to item records; the product task uses sid2iid.json. One SID may map to several items, so the task's selection strategy and mapping metadata matter. This base-8192 convention belongs to that dataset, not to every model or catalog.

    The repository's dataset catalog converter reads the mapping's keys to produce token sequences. Keep the original mapping: the resulting catalog/triples do not retain its item records. Use the matching dataset release, task, item-selection policy, and ground truth when evaluating recommendations. A legal SID, or a randomly initialized SID checkpoint that executes successfully, does not establish useful recommendations or Recall.

    Continue with Python integration to load this exact configuration from an application, or use Online serving, Beam parameters and modes, or Validation and benchmarking. For input, digest, and tokenizer failures, see Troubleshooting.

    The pinned sources are the triples converter, artifact builder, artifact loader, and tokenizer digest contract.
