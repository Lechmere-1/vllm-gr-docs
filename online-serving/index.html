    Online serving¶

    Serve OneRec Beam Search through an OpenAI-compatible HTTP endpoint on CUDA or Ascend NPU. This guide starts one local server and sends one prompt with Beam width 128 and three generated SID components.

    Complete the platform installation or Ascend installation, then follow First offline inference to download the model and check the inference path. Run these commands from the vllm-gr repository root in the same accelerator environment. Stop the offline process before starting the server so it can use the device memory.

    Already prepared an artifact and YAML with Data and constraints? Keep its MODEL, BACKEND, and WORKDIR in the server shell and continue at Start the server. The commands read $WORKDIR/vllm_gr_config.yaml; you do not need to rebuild the same artifact. The client terminal below uses its own output directory.

    1. Set the paths and platform¶

    Use the same local model snapshot and example constraint data as the offline guide. Set MODEL to your actual model directory if it differs:

    export MODEL="$PWD/models/OneRec-1.7B"
export CATALOG="$PWD/tools/AB_Tests/constraints/video_constraint_triples.json"
export WORKDIR="$PWD/results/online-serving"
mkdir -p "$WORKDIR"
test -f "$MODEL/config.json"
test -f "$CATALOG"

    Choose one backend, then run the common configuration step below:

    export BACKEND=cuda

    export BACKEND=npu

    For NPU, keep the CANN and custom xllm-ops environments loaded in this shell, as described in the Ascend installation guide.

    2. Build the artifact and server configuration¶

    The service loads a persistent .safetensors Constraint Table. It does not accept the triples JSON as a server-side catalog argument. The following uses the repository's artifact builder and writes a canonical YAML configuration with the resulting absolute path and digests:

    python - <<'PY'
import os
from pathlib import Path
import yaml
from tools.build_constraint_table import build_constraint_table
from vllm_gr.config import gr_config_from_mapping

backend = os.environ["BACKEND"]
if backend not in {"cuda", "npu"}:
    raise ValueError("BACKEND must be cuda or npu")
work = Path(os.environ["WORKDIR"]).resolve()
artifact = work / "video_constraint_table.safetensors"
artifact_digest, tokenizer_digest, _ = build_constraint_table(
    triples_path=os.environ["CATALOG"],
    model=str(Path(os.environ["MODEL"]).resolve()),
    revision=None,
    output_path=artifact,
    trust_remote_code=True,
)
config = {
    "schema_version": 1,
    "attention_backend": "CUSTOM",
    "beam": {
        "execution_mode": "v1",
        "graph_enabled": backend == "cuda",
        "graph_batch_size": 1,
        "online_batch_sizes": [1],
        "worker_decision": True,
        "max_width": 128,
        "max_decode_steps": 3,
    },
    "constraint_table": {
        "enabled": True,
        "backend": backend,
        "max_top_k": 128,
        "path": str(artifact),
        "format": "constraint_table_v1",
        "artifact_digest": artifact_digest,
        "tokenizer_digest": tokenizer_digest,
    },
}
gr_config_from_mapping(config)
config_path = work / "vllm_gr_config.yaml"
config_path.write_text(yaml.safe_dump(config, sort_keys=False), encoding="utf-8")
print(f"config={config_path}")
print(f"artifact_digest={artifact_digest}")
print(f"tokenizer_digest={tokenizer_digest}")
PY

    Keep the artifact and YAML available at these paths while the server runs. Rebuild them when the constraint data or tokenizer changes. This preparation compiles the table; it does not run model inference. See Data and constraints for alternate catalog inputs and Python integration to load the same configuration without an HTTP server.

    Configuration Purpose
    constraint_table.backend Match the accelerator running the server.
    path and the two digests Identify the artifact and the tokenizer used to compile it.
    beam.max_width: 128 Match the request's Beam width.
    beam.max_decode_steps: 3 Allocate the three-component SID generation budget.
    beam.online_batch_sizes: [1] Keep the initial example to one prompt per execution session.
    beam.graph_enabled Keep CUDA's graph path; start NPU in eager mode.

    Do not add legacy flags such as --catalog-path, --beam-max-width, or a second attention-backend override alongside --vllm-gr-config.

    3. Start the server¶

    Run the command matching the backend used to generate the YAML. Leave this terminal running until you finish the client request.

    vllm-gr serve "$MODEL" \
  --host 127.0.0.1 --port 8000 \
  --served-model-name onerec --trust-remote-code \
  --vllm-gr-config "$WORKDIR/vllm_gr_config.yaml" \
  --max-model-len 512 --max-num-batched-tokens 512 \
  --max-num-seqs 128 --max-logprobs 128 \
  --gpu-memory-utilization 0.5 \
  --async-scheduling --no-enable-chunked-prefill

    vllm-gr serve "$MODEL" \
  --host 127.0.0.1 --port 8000 \
  --served-model-name onerec --trust-remote-code \
  --vllm-gr-config "$WORKDIR/vllm_gr_config.yaml" \
  --max-model-len 512 --max-num-batched-tokens 512 \
  --max-num-seqs 128 --max-logprobs 128 \
  --gpu-memory-utilization 0.5 --block-size 128 \
  --enforce-eager \
  --async-scheduling --no-enable-chunked-prefill

    The short prompt below fits the 512-token model and Prefill budgets. Keep asynchronous scheduling enabled and Chunked Prefill disabled for this V1 path. Startup can include model loading and compilation; wait for the server to be ready before sending requests.

    NPU graph execution

    The NPU example uses beam.graph_enabled: false and --enforce-eager. To try the NPU graph path later, set beam.graph_enabled: true in the YAML, remove --enforce-eager, and restart the server. Keep graph_batch_size: 1 for this single-prompt example. Graph execution and numerical parity are separate validation tasks.

    4. Send a request¶

    Open a second terminal on the same accelerator host, activate the client Python environment, and return to the repository root. Set these variables again; shell variables from the server terminal are not inherited:

    export API=http://127.0.0.1:8000
export WORKDIR="$PWD/results/online-serving"
mkdir -p "$WORKDIR"

curl --fail --silent --show-error "$API/health"
curl --fail --silent --show-error "$API/v1/models" | python -m json.tool

    /health should return HTTP 200, and /v1/models should list the configured name onerec. Write the request as JSON using Python, so prompt newlines and quotes are escaped correctly:

    python - <<'PY'
import json
import os
from pathlib import Path

request = {
    "model": "onerec",
    "prompt": (
        "Video history: <|sid_begin|><s_a_346><s_b_6566><s_c_5603><|sid_end|>.\n"
        "Recommend the next video."
    ),
    "use_beam_search": True,
    "stream": False,
    "n": 128,
    "temperature": 0.0,
    "max_tokens": 5,
    "ignore_eos": True,
    "skip_special_tokens": False,
    "include_stop_str_in_output": True,
    "vllm_xargs": {
        "begin_token": "<|sid_begin|>",
        "end_token": "<|sid_end|>",
    },
}
path = Path(os.environ["WORKDIR"]) / "request.json"
path.write_text(json.dumps(request, ensure_ascii=False, indent=2), encoding="utf-8")
print(path)
PY

curl --fail-with-body --silent --show-error \
  "$API/v1/completions" \
  -H 'Content-Type: application/json' \
  --data-binary "@$WORKDIR/request.json" \
  --output "$WORKDIR/response.json" \
  --write-out 'HTTP elapsed: %{time_total}s\n'

    This uses the completions endpoint with a text prompt, without a chat template. The online path does not apply the offline demo's --input-len padding or truncation, so the two examples do not establish identical token shapes or latency.

    Request field Meaning
    model: onerec Match --served-model-name, rather than the local directory name.
    use_beam_search: true Select Beam Search instead of ordinary sampling.
    n: 128 Set the Beam width to the server's configured width. It is not a display limit.
    max_tokens: 5 Reserve begin and end positions, leaving three generated SID components. The first component comes from Prefill, followed by two Decode steps.
    ignore_eos: true State V1's fixed-budget behavior. The online V1 entry supplies this value even if a client sends false.
    stream: false Receive one complete response with the final candidates.
    vllm_xargs Supply the SID begin and end tokens as Beam extensions.

    5. Read the response¶

    Inspect the returned count and the first five choices:

    python - <<'PY'
import json
import os
from pathlib import Path

path = Path(os.environ["WORKDIR"]) / "response.json"
response = json.loads(path.read_text(encoding="utf-8"))
if "error" in response:
    raise SystemExit(response["error"])
print(f"returned_choices={len(response['choices'])}")
for choice in response["choices"][:5]:
    print(choice["index"], choice["finish_reason"], choice["text"])
print("usage=", response.get("usage"))
PY

    choices[].text contains the SID candidate text, index identifies the choice, and finish_reason describes completion. A length finish reason can be normal for this fixed-budget search; the output processor adds the configured end marker to surviving fixed-length candidates. The returned count can be below 128 when there are fewer valid candidates.

    usage contains HTTP response token accounting. The offline example's sid_token_ids and cumulative_logprob JSON fields are not part of this HTTP response contract. This guide does not request per-token log probabilities.

    The printed HTTP elapsed time is client-observed wall time, including HTTP overhead and any request queueing. It is not device kernel time or a steady-state benchmark. Use representative inputs and repeated controlled runs to measure latency and recommendation quality.

    Troubleshooting¶

    Symptom What to check
    Connection refused Keep the server terminal running, wait for startup, and use the same host and port as the command.
    Model not found in the request Use model: onerec, matching the server alias; inspect /v1/models.
    Width validation error Keep request n equal to beam.max_width, both 128 here.
    Artifact, digest, or tokenizer mismatch Regenerate the artifact and YAML together from the same model snapshot and catalog.
    Engine initialization fails for memory Check the startup error and available device memory; avoid sharing a busy accelerator.
    Prompt does not fit the token budget This example uses 512 tokens. Increase the model and Prefill budgets together for longer complete prompts, within model and device limits.
    HTTP request fails Read response.json and the server log for the specific error; the curl command returns a nonzero status on HTTP errors.

    This example intentionally uses a single prompt. The engine has a separate prompt-list batching policy; see the batching reference before enabling additional sizes. Full configuration details are in the online example.

    Continue with Beam parameters and modes before adjusting widths, generation budgets, or graph shapes. See Validation and benchmarking for correctness checks and offline API latency measurements with an explicit timing boundary. For startup failures, HTTP errors, or artifact mismatches, use Troubleshooting.
