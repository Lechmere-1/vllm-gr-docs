    Advanced Beam workflows¶

    Choose one advanced workflow after the first offline request works. These routes describe source snapshot c4966f18; their presence is not a claim of hardware validation for every model or combination. Keep models and capabilities and validation alongside the examples. Reuse the local model snapshot from Quickstart. Selecting a mode does not add SID tokens, trained recommendation weights, or thinking ability to a checkpoint.

    Goal Change Keep separate
    Spend fewer or more rows at later stages Dynamic retained widths Engine capacity and final return limit
    Search without a business catalog Unconstrained Beam configuration Ordinary sampled text generation
    Emit A/B/C families without catalog membership NPU SID stage domain Full-vocabulary probability normalization
    Think before selecting SIDs The offline demo's combined --cot workflow Thinking budget and SID generation budget
    Limit each parent's candidates or choose catalog roots CUDA request/configuration extensions NPU capabilities in this snapshot

    Narrow or widen the active Beam¶

    Use the dynamic-width examples for runnable NPU commands. Keep engine beam.max_width and request beam_width at 128; a schedule changes retained prefixes, not that capacity:

    Retained widths after A/B/C Decode input widths Final return limit example
    [128, 64, 32] 128, 64 result_width=16
    [32, 64, 128] 32, 64 result_width=16

    The last retained width has no following model forward. NPU Beam graphs match exact (logical_batch_size, Decode_input_width) shapes. The demo derives its capture widths; a custom integration must configure them before engine startup. The maximum-capacity width is also captured. See NPU graph shapes for the capture-count limit and fallback behavior.

    Leave scalar constraint_table.candidate_width unset for changing NPU widths. NPU's current path does not support independent candidate schedules. Python and HTTP expose dynamic retained widths on CUDA too, although the standalone demo's dynamic CLI flags are NPU-only. Narrowing prunes prefixes; later widening cannot recover them. Validate recommendation quality for the chosen search.

    Search the full vocabulary without a catalog¶

    The catalog-based offline demo does not have an unconstrained Beam CLI flag. Use GRLLM.beam_search_v1() with an explicitly disabled table instead. This is Beam Search, not GRLLM.generate() sampling, and outputs need not be SIDs.

    The following is a modification fragment, not a standalone program. Adapt the complete Python integration inside its main(): replace the entire block from config = load_gr_config(...) through the final candidate-capacity check with this configuration, then replace params. Keep the earlier backend/model checks, main guard, context manager, native engine settings, and compact-output handling. Recompute candidate_width as shown; the existing constructor uses it in max_logprobs=candidate_width. Use BACKEND=npu, ModelRunner V1, block_size=128, and enforce_eager=True for this initial case. Do not append this fragment after checks requiring an enabled catalog table.

    from vllm_gr.config import gr_config_from_mapping, resolve_candidate_width

mode_config = {
    "schema_version": 1,
    "attention_backend": "CUSTOM",
    "constrained_generation": False,
    "beam": {
        "execution_mode": "v1",
        "worker_decision": True,
        "graph_enabled": False,
        "graph_batch_size": 1,
        "online_batch_sizes": [1],
        "max_width": 128,
        "max_decode_steps": 3,
    },
    "constraint_table": {
        "enabled": False,
        "backend": "npu",
        "max_top_k": 128,
    },
}
config = gr_config_from_mapping(mode_config)
candidate_width = resolve_candidate_width(config)
params = BeamSearchParams(
    beam_width=128, max_tokens=3, temperature=0.0, ignore_eos=True
)

    No artifact path, artifact/tokenizer digest, or vocabulary slice is configured. The request omits BEGIN/END positions, so max_tokens=3 means three generated tokens, and no BEGIN is appended; update any integration log saying otherwise. Keep complete prompt tokenization and enforce its context budget.

    The NPU adapter in this snapshot supports only one, two, or three generated tokens, ModelRunner V1, a supported plain text decoder in FP16/BF16, asynchronous scheduling, disabled Chunked Prefill, and TP/PP/DP/DCP/PCP=1. Existing Beam attention/KV dependencies remain required. The selector does not promise a performance gain over constrained TopK. See the complete unconstrained contract for configuration and finite-logit handling. Longer ordinary LLM generation does not extend this NPU Beam horizon.

    Restrict NPU token families without a catalog¶

    SID stage mode is an optional specialization of the unconstrained configuration. Before constructing a new engine, change the preceding fragment as follows:

    mode_config["beam"]["sid_stage_vocab"] = True
config = gr_config_from_mapping(mode_config)
candidate_width = resolve_candidate_width(config)
params = BeamSearchParams(
    beam_width=128,
    max_tokens=5,
    temperature=0.0,
    ignore_eos=True,
    begin_token="<|sid_begin|>",
    end_token="<|sid_end|>",
    include_stop_str_in_output=True,
)

    After choosing either unconstrained variant's params, check its request boundary before constructing the engine. Retain the Python integration's nonempty-prompt and full-context-budget checks before the Beam call:

    effective_steps = (
    params.max_tokens - int(params.begin_token is not None)
    - int(params.end_token is not None)
)
if params.beam_width != config.beam_max_width:
    raise ValueError("Request width must match the configured capacity")
if not 1 <= effective_steps <= min(3, config.beam_max_decode_steps):
    raise ValueError("Keep the NPU effective budget within 1..3 and engine capacity")

    The SID-stage variant uses OneRec's markers and matching tokenizer. Supply the model's intended prompt; the API adds BEGIN, so do not add another copy yourself. Prefill selects A, followed by B and C in two Decode forwards. Token families come from the tokenizer's registered <s_a_N>, <s_b_N>, and <s_c_N> IDs. The stage domain is NPU-only, opt-in, and limited to three components.

    Every combination within those families is eligible; there is no catalog membership check. Scores are normalized over the complete current SID family, not the full vocabulary or only the selected TopK candidates. Changing that domain can change scores and cross-parent rankings.

    VLLM_GR_NPU_STAGE_LM_HEAD=0 disables the stage-projection optimization while preserving the same SID domain, providing a reference for that optimization. It does not restore full-vocabulary probabilities. Setting the variable to 1 alone does not enable SID stage mode. Set it before starting a fresh process; compare implementations under the same domain and inputs.

    Generate thinking text, or think before SID Beam¶

    Both thinking modes require a compatible checkpoint and preserve the complete input. The combined mode also requires dedicated <think> and </think> tokens plus a matching SID catalog. A flag cannot add reasoning proficiency to untrained weights. Keep the NPU environment from the installation guide loaded.

    The commands below reuse MODEL and CATALOG from Data and constraints, and create a separate full prompt. Keep the model's own intended question/history when replacing it:

    export COT_DIR="$PWD/results/advanced-beam"
export THINK_PROMPT="$COT_DIR/prompt.txt"
mkdir -p "$COT_DIR"
export VLLM_WORKER_MULTIPROC_METHOD=spawn
export VLLM_USE_V2_MODEL_RUNNER=0
cat > "$THINK_PROMPT" <<'EOF'
Video history: <|sid_begin|><s_a_346><s_b_6566><s_c_5603><|sid_end|>.
Consider this history and recommend the next video.
EOF

    Choose one mode, not both:

    python -u examples/offline_inference/beam_search/offline_beam_search_v1.py \
  --model "$MODEL" --prompt "$THINK_PROMPT" \
  --constraint-backend npu --execution eager \
  --batch-size 1 --enable-thinking \
  --max-tokens 1024 --max-model-len 8192 \
  --temperature 0 --top-p 1 --top-k -1 \
  --output-json "$COT_DIR/thinking.json"

    python -u examples/offline_inference/beam_search/offline_beam_search_v1.py \
  --model "$MODEL" --catalog "$CATALOG" --prompt "$THINK_PROMPT" \
  --constraint-backend npu --execution eager \
  --batch-size 1 --beam-width 128 --generated-steps 3 \
  --cot --cot-max-tokens 1024 --cot-on-limit error --max-model-len 8192 \
  --temperature 0 --top-p 1 --top-k -1 --print-beams 5 \
  --output-json "$COT_DIR/cot-beam.json"

    --enable-thinking uses ordinary generation with constraints disabled and no SID Beam phase. Its --max-tokens covers the complete continuation, including any thinking and final answer. --cot-max-tokens instead limits the combined mode's thinking phase; --generated-steps still controls SID components. The complete prompt, thinking allowance, separator, and SID boundaries must fit --max-model-len. Both modes ignore --input-len; do not truncate the question to make the thinking budget fit.

    Plain text uses the checkpoint's chat template. Serialized Qwen ChatML needs real line breaks or one complete JSON string; bare ChatML with ambiguous literal \n is rejected. The parser preserves earlier messages and reopens only the supported terminal empty assistant/thinking prefix. Read the input and handoff contract before using serialized prompts.

    The default combined policy requires a natural </think> before Beam starts. An unclosed span, including an early EOS, fails the batch. If you deliberately choose --cot-on-limit truncate, only a real length-budget exhaustion permits forced closure; every token is retained and the report marks truncation and forced closure. This is not a naturally completed thought. Other incomplete stop conditions still fail. Increase the budget or fix the model/prompt first.

    Both phases use one loaded engine but hand off token IDs with separate cache salts and a fresh Beam Prefill; thinking KV is not reused across phases. This does not extend the three-level SID table. The source workflow documents NPU commands; CUDA hardware validation of the combined example is not included.

    CUDA per-parent candidates and multiple catalog roots¶

    On CUDA, adapt only the request parameters in the constrained Python example to limit candidates from each parent while retaining width 128. This is also a fragment for an already configured engine with sufficient candidate capacity:

    params = BeamSearchParams(
    beam_width=128,
    per_parent_beam_widths=[128, 8, 4],
    result_width=16,
    max_tokens=5,
    temperature=0.0,
    ignore_eos=True,
    begin_token="<|sid_begin|>",
    end_token="<|sid_end|>",
    include_stop_str_in_output=True,
)

    The first candidate count equals the first retained width. Later retained widths cannot exceed the previous width times that stage's candidate count. Global selection still chooses the winners; no parent has a survival quota. HTTP carries the schedule in vllm_xargs.per_parent_beam_widths. There is no corresponding standalone-demo flag, and NPU rejects this schedule here.

    For multiple CUDA catalogs, the Multi-Trie workflow uses tools/build_constraint_table.py --tries with a manifest of separately prepared triples documents. Use its emitted digests and constraint_table_v2 format, then pass one trie_ids value per prompt to the Python Beam call; completions HTTP uses vllm_xargs.trie_ids. Selectors are separate from BeamSearchParams.

    All roots share one model vocabulary and tokenizer. Trie IDs start at zero and belong to the loaded artifact; choosing a root does not switch models. Omission selects root zero, while an out-of-range selector is rejected rather than becoming unconstrained. NPU currently accepts only one Trie and root zero. CPU compilation/reference support does not establish CPU Beam inference.

    Measure each route with matching inputs and its own probability domain. See Validation and benchmarking and Troubleshooting for precision and graph diagnostics.
