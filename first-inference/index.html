    First offline inference¶

    New to the project? Follow Quickstart for the installation and first-run sequence. This page contains the detailed commands and output guide.

    Run a single constrained OneRec Beam Search request on CUDA or Ascend NPU. This guide uses the repository's example constraint data, a short prompt, batch size 1, Beam width 128, and three generated SID components.

    Complete the CUDA installation or Ascend NPU installation first. Run every command below in a Bash shell from the vllm-gr repository root, using that installation's Python environment. For Ascend, stay inside the prepared vendor container and load the CANN and custom xllm-ops environments described in the installation guide.

    1. Check the runtime¶

    Select an available accelerator using your environment's device allocation rules, then check the installed packages:

    nvidia-smi
vllm-gr check-env

    npu-smi info
vllm-gr check-env --npu

    check-env checks runtime compatibility; it does not run a model or prove that enough device memory is available. Avoid devices occupied by other inference jobs.

    2. Prepare the model and prompt¶

    The framework repository does not include model weights. Download OpenOneRec/OneRec-1.7B, or point MODEL at an existing local copy of that model. Keep the weights, configuration, and tokenizer from the same snapshot.

    export MODEL="$PWD/models/OneRec-1.7B"
export WORKDIR="$PWD/results/first-inference"
mkdir -p "$WORKDIR"

    If the model is not already available, download it with the installed huggingface_hub library. This resolves one immutable model revision and uses it for the entire download. Keep the printed revision with your run records.

    python - <<'PY'
import os
from huggingface_hub import HfApi, snapshot_download

repo = "OpenOneRec/OneRec-1.7B"
revision = HfApi().model_info(repo).sha
snapshot_download(repo_id=repo, revision=revision, local_dir=os.environ["MODEL"])
print(f"model_revision={revision}")
PY

    See the Hugging Face download guide for authentication and download options.

    Use the example triples document already tracked in the source repository:

    export CATALOG="$PWD/tools/AB_Tests/constraints/video_constraint_triples.json"
export PROMPT="$WORKDIR/prompt.txt"

cat > "$PROMPT" <<'EOF'
Video history: <|sid_begin|><s_a_346><s_b_6566><s_c_5603><|sid_end|>.
Recommend the next video.
EOF

test -f "$MODEL/config.json"
test -f "$CATALOG"
test -f "$PROMPT"

    This prompt and example catalog check that the inference path works. Use your own model-aligned catalog, representative prompts, and an evaluation dataset to measure recommendation quality or Recall.

    3. Run Beam Search¶

    Choose the tab matching your installed runtime:

    python -u examples/offline_inference/beam_search/offline_beam_search_v1.py \
  --model "$MODEL" \
  --catalog "$CATALOG" \
  --prompt "$PROMPT" \
  --constraint-backend cuda \
  --batch-size 1 --beam-width 128 \
  --input-len 128 --generated-steps 3 \
  --print-beams 5

    python -u examples/offline_inference/beam_search/offline_beam_search_v1.py \
  --model "$MODEL" \
  --catalog "$CATALOG" \
  --prompt "$PROMPT" \
  --constraint-backend npu --execution eager \
  --batch-size 1 --beam-width 128 \
  --input-len 128 --generated-steps 3 \
  --print-beams 5

    The script compiles a temporary Constraint Table from the triples document and the model tokenizer, loads the model, and calls GRLLM.beam_search_v1(). The temporary artifact is removed when the script exits. Startup, compilation, and graph capture can make the first run slower than later requests.

    Setting Meaning in this example
    --model A local model directory, including its tokenizer and weights.
    --catalog A triples JSON document, not an arbitrary catalog JSON or a .safetensors artifact.
    --batch-size 1 Submit one prompt. Larger batches repeat the same prepared prompt in this script.
    --beam-width 128 Set both engine Beam capacity and request width to 128.
    --generated-steps 3 Generate the A, B, and C SID components; the first component comes from Prefill.
    --input-len 128 Prepare 127 prompt tokens, then let V1 append the begin token. Long inputs are truncated from the left; short inputs are left-padded with newline tokens.
    --print-beams 5 Print at most five returned candidates without reducing the search width.

    The example sets asynchronous scheduling, disables Chunked Prefill, and keeps request width and engine capacity consistent. Keep the first run unchanged before adjusting advanced options.

    Execution modes

    --execution only controls the NPU path. The NPU command above starts in eager mode. After it works, change --execution eager to --execution graph to check NPU Decode graph capture and replay; this three-step run prints npu_beam_graph counters and fails if the expected replay is not observed. This option does not disable CUDA's existing graph behavior. A successful graph run establishes execution, not identical scores for every input shape.

    4. Read the output¶

    For each request, the script prints request=0 returned_beams=..., followed by JSON records for the first few candidates:

    Field Meaning
    request, rank Request index and candidate rank, starting at zero.
    cumulative_logprob The candidate's cumulative log probability.
    sid_token_ids The trailing generated SID slice as token IDs.
    sid_tokens The same slice as token strings. For this three-step example, expect begin, A, B, C, and end positions.
    finish_reason, stop_reason Completion metadata from the Beam output.

    The returned count depends on valid candidates and can be smaller than the requested width. SID components identify a catalog item through the matching SID-to-item mapping; they are not natural-language recommendation explanations. Scores and rankings are not fixed reference values across devices or batch shapes.

    5. Prepare a reusable Constraint Table (optional)¶

    For the complete catalog-to-artifact workflow, follow Data and constraints. To use the artifact in your own program, continue with Python integration.

    For an application that loads a persistent artifact, compile it separately:

    python tools/build_constraint_table.py \
  --triples "$CATALOG" \
  --model "$MODEL" \
  --output "$WORKDIR/video_constraint_table.safetensors" \
  --trust-remote-code

    The command prints artifact_digest, tokenizer_digest, and vocab_size. Use the artifact's absolute path and both digests in your application's constraint_table configuration. Rebuild it when the tokenizer or constraint data changes. The standalone script above always compiles its own temporary artifact; it does not read this saved file.

    For the full dataset-to-catalog conversion, follow the OneRec data preparation guide. See the configuration reference for artifact fields and platform settings.

    Troubleshooting¶

    Symptom What to check
    FileNotFoundError for the model, catalog, or prompt Run from the repository root and check the absolute paths exported above. Weights must be downloaded separately.
    tee: ... No such file or directory Create the log's parent directory before piping output to tee.
    Tokenizer or Constraint Table validation error Use a model with the matching SID tokens and compile with that exact tokenizer snapshot.
    Free device memory is below the requested utilization Select a free device or reduce --gpu-memory-utilization if enough memory remains for the workload. The default is 0.5, including on NPU.
    NPU custom operators cannot load Reload the CANN and xllm-ops environments from the Ascend installation guide in the active shell.
    NPU graph capture or replay is not observed Confirm the eager command works first, then keep the same inputs and select --execution graph.

    This guide covers three-component constrained Beam Search. Unconstrained generation, thinking, dynamic Beam schedules, and multi-Trie inputs have separate configuration contracts; do not combine their options with the first-run command. Use the troubleshooting guide for diagnosis and Models and capabilities before switching modes.
